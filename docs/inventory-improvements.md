# Бараа материалын сайжруулалтууд

> Системийг цааш хөгжүүлэх саналууд. Эрэмбэлбэр: P0 → P3 (ноцтой байдлын дагуу).

---

## Зорилго

Одооны систем нь "цахим бүртгэл"-ийн түвшинд байна. Жинхэнэ ашигтай болгохын тулд **бичгээр бичдэг дадлыг орлох** хэрэгтэй — бага алхам, илүү хурдан, алдаа багатай.

---

## P0 — Хамгийн чухал (Бодит асуудал шийднэ)

### 1. Сүүлд ашигласан / Түгээмэл сэлбэг (Quick-Add)

**Асуудал:** Механикууд ажлын дараа аль сэлбэг ашигласанаа мартдаг. "Нээх → хайх → нэмэх" гэдэг 5 алхам хэтэрхий их.

**Шийдэл:** Ажлын захиалгын хуудас дээр **сүүлд ашигласан / түгээмэл сэлбэгийн товчлол** харуулах.

| Бүрэлдэхүүн | Тайлбар |
|-------------|---------|
| **Recent** | Энэ механикын өнөөдөр ашигласан сэлбэгүүд (автомат) |
| **Popular** | Энэ байгууллагын хамгийн түгээмэл 20 сэлбэг |
| **Favorites** | Механик өөрийнхөө хүссэн сэлбэгүүд (custom) |

**Ажиллах явц:**
1. Ажлын захиалга нээх → барааны хэсэгт "Quick Add" хавтас
2. Нэг дарахад → сэлбэг нэмэгдэнэ (тоо = 1)
3. Тоог өөрчлөх боломжтой (хэрэв хооронд нь 2-3 ширхэг ашигласан бол)

**Үр дүн:** 5 алхам → 1 даралт. Бичгээр бичих шаардлагагүй.

### 2. Энгийн хайлт + Дуут хайлт

**Асуудал:** Монгол нэр, Англи нэр, дугаар гээд олон зүйл бичих хэрэгтэй. Заримдаа нэрийг нь мэдэхгүй.

**Шийдэл:**

| Хайлтын төрөл | Хэрхэн ажиллах |
|---------------|----------------|
| **Текст хайлт** | Нэр, Монгол нэр, Part #, Ангилал дээр хайна |
| **Дуут хайлт** | Микрофоныг дарж хэлэх → "Тосны шүүр" → олно |
| **Зурагтай хайлт** | Зураг авах → төстэй сэлбэгүүдийг харуулна (ирээдүй) |

**Дуут хайлтын технологи:**
- Web Speech API (бүх modern хөтөч дэмжинэ)
- Mongolian language support хэрэгтэй (SpeechRecognition lang = 'mn')
- Хэрэггүй бол textarea-д бичих хэвээр

### 3. Хүрэлцэхгүй байгаа барааны цахим хүсэлт

**Асуудал:** Механик хэрэгтэй сэлбэгээ олохгүй болохоор "захиалчих" гэж хэлдэг. Дараа нь мартна.

**Шийдэл:** Ажлын захиалгын хуудас дээр **"Хэрэгтэй бараа"** товч:

1. Товч дарах → хайх цонх нээгдэнэ
2. Сэлбэг сонгох (эсвэл бичих)
3. "Хүсэлт илгээх" → нийлүүлэгчийн хүсэлтийн жагсаалт руу шилжинэ
4. Менежер PO үүсгэхдээ эдгээр хүсэлтийг нэмнэ

---

## P1 — Өндөр үнэ цэнэ (Бизнесийг өөрчилнэ)

### 4. Тавиурын байршил (Shelf Location)

**Асуудал:** "Тосны шүүр хаана байна?" — энэ асуултыг өдөрт 10 удаа асуудаг. Цаг алддаг.

**Шийдэл:** `parts_catalog` руу `location` нэмэх:

```
location: "A-3-12"  → Тавиар A, Ширээ 3, Үйрдэр 12
```

| Үйлдэл | Хэрхэн ажиллах |
|--------|----------------|
| **Байршил нэмэх** | PartForm дээр "Байршил" талбар (жишээ: A-3-12) |
| **Хайх** | Parts жагсаалтад "Байршил" багана нэмэх |
| **Хаана байгааг харуулах** | Дэлгэрэнгүй хуудас дээр "📍 A-3-12" гэж харуулна |
| **Хайлт** | "A-3" гэж бичихэд тавиар A-д байгаа бүх сэлбэг гарна |

**Жин чухал:** Шинэ сэлбэг нэмэхдээ байршил бичих, хуучин сэлбэгүүдэд нэг бүрчлэн нэмэх.

### 5. Урьдчилсан нөөц тооцоо (Predictive Reorder)

**Асуудал:** Одооны систем зөвхөн "босго доор унасан" үед хэлдэг. Хэтэрхий оройтсон байх тохиолдол их.

**Шийдэл:** Хэрэглээний түүхээс тооцоолох:

```
Дундаж хэрэглээ = Сүүлийн 90 хоногийн sale movement / 90
Хоногийн хэрэглээ = Дундаж хэрэглээ
Үлдсэн хоног = quantity_on_hand / Хоногийн хэрэглээ

Хэрэв Үлдсэн хоног < Supplier lead time бол → Анхааруулга
```

| Элемэнт | Тайлбар |
|---------|---------|
| **Хоногийн хэрэглээ** | Parts дэлгэрэнгүй хуудас дээр харуулна |
| **Үлдсэн хоног** | "12 хоног үлдсэн" гэж харуулна |
| **Автомат PO санал** | PO үүсгэхдээ хэрэглээний түхэлгээр тооцно |

**Нэмэлт:** Нийлүүлэгч бүрд **lead time** (хүлээх хугацаа) тохируулах:

| Нийлүүлэгч | Lead Time | Тайлбар |
|------------|-----------|---------|
| Дотоод | 0 хоног | Агуулахад байгаа |
| Хятад | 14-30 хоног | Импорт |
| Орон нутаг | 1-3 хоног | Дотоод нийлүүлэгч |

### 6. Ажлын захиалгатай холбогдсон хэрэглээний түүх

**Асуудал:** "Энэ Camry-д өмнө нь юу сольсон бэ?" гэдгийг мэдэхгүй.

**Шийдэл:** Vehicle → Work Orders → Parts Used гэсэн холбоос:

| Талбар | Тайлбар |
|--------|---------|
| **Тээврийн хэрэгсэл** | Машин сонгох |
| **Ажлын захиалгууд** | Энэ машинд хийсэн бүх ажлууд |
| **Ашигласан сэлбэг** | Бүр ажлын захиалгад ашигласан сэлбэгүүд |
| **Дараагийн солих** | "Brake pad сольсон — дараагийн удаа 10,000 км-ийн дараа" |

**Үр дүн:** Захиалга өгөхөд "өмнө нь энэ машинд brake pad сольсон, дахиад солих цаг болжээ" гэж хэлж чадна.

## P2 — Дунд зэрэг (Бизнесийг сайжруулна)

### 7. Эргэлтийн тооцоо (Cycle Counting)

**Асуудал:** Жилд нэг удаа тооллого хийх гээд бүх өдрийг алддаг. Тэгэхдээ зөрүү гардаг.

**Шийдэл:** Мобайлд зориулсан энгийн тооцоо:

1. Ангилал сонгох (жишээ: "Тос")
2. Тавиар бүрээр тоолох
3. Нэг бүрийг тоогоор бүртгэх
4. Систем хүлээгдэж буй тоотой харьцуулна
5. Зөрүүтэйг улаан өнгөөр харуулна
6. "Баталгаажуулах" → зөрүүгээр шинэчилнэ (adjustment movement)

**Хугацаа:** Өдөрт 10-15 минут (нэг тавиар). Жилд нэг удаагийн оронд сард нэг удаа.

### 8. Нийлүүлэгчийн үнийн харьцуулалт

**Асуудал:** Нэг сэлбэгийг олон нийлүүлэгчээс авдаг. Хамгийн хямдыг нь мэдэхгүй.

**Шийдэл:** PO үүсгэхдээ нийлүүлэгч бүрийн үнийг харуулах:

| Сэлбэг | Нийлүүлэгч A | Нийлүүлэгч B | Нийлүүлэгч C |
|--------|-------------|-------------|-------------|
| Тосны шүүр | 8,000₮ | 7,200₮ ✅ | 7,800₮ |
| Brake pad | 45,000₮ | 42,000₮ ✅ | 48,000₮ |

**Нэмэлт:** Сүүлийн худалдан авалтын үнийн түүх (purchase price history).

### 9. Хаягдал / Буцаалтын шалтгаан

**Асуудал:** "Хог" гэж бүртгэдэг ч яагаад хаясан нь мэдэгдэхгүй.

**Шийдэл:** Movement үүсгэхдээ **шалтгаан сонгох**:

| Movement Type | Шалтгаанууд |
|---------------|------------|
| **waste** | Гэмтсэн, Хугацаа дууссан, Буруу сэлбэг, Чанар муу |
| **return** | Буруу илгээсэн, Чанарын асуудал, Захиалга цуцалсан |

**Тайлан:** "Сүүлийн сард 320,000₮-ийн хаягдал гарсан — үүнээс 60% нь буруу сэлбэг" гэж харуулна.

### 10. Баркод label хэвлэх

**Асуудал:** Шинэ сэлбэг ирэхэд тавиур дээр шошго наахгүй. Дараа нь мэдэхгүй.

**Шийдэл:** Сэлбэг нэмэхэд **шошго хэвлэх** товч:

- Бүх мэдээлэл нэг шошгон дээр: Нэр, Дугаар, Ангилал, Үнэ, Байршил
- Баркод (Code128 эсвэл QR) — дараа нь скан хийхэд ашиглах
- Бага өртөгтэй термо принтертэй ажиллана (DYMO, Brother QL)

## P3 — Ирээдүй (Төсөл хэрэгжүүлэхэд бэлэн болоход)

### 11. Зурагтай хайлт (Visual Search)

**Асуудал:** Механик ямар сэлбэг хэрэгтэйгээ мэддэг ч нэрийг нь мэдэхгүй.

**Шийдэл:**
1. Зураг авах (утасны camera)
2. Систем зургийг анализ хийнэ
3. Ангилал болон төстэй сэлбэгүүдийг харуулна
4. Механик сонгоно

**Технологи:** Image embedding + vector search (Supabase pgvector ашиглах боломжтой).

### 12. Утастай хайлт (Voice Search)

**Асуудал:** Гараа бохирologue механик гар утсаа барьж бичиж чадахгүй.

**Шийдэл:**
- Микрофоныг дарж хэлэх → "Тосны шүүр" → хайлтын үр дүн
- Web Speech API ашиглах (Chrome, Safari дэмжинэ)
- Mongolian language support хэрэгтэй

**Нэмэлт:** "Би Toyota Camry-д brake pad хэрэгтэй" → brake pad-уудыг харуулна.

### 13. Автомат нийлүүлэгч сонгох

**Асуудал:** PO үүсгэхдээр нийлүүлэгчийг гаргаар сонгодог.

**Шийдэл:**
- Сэлбэг бүрийн **хамгийн сүүлийн үнийг** нийлүүлэгч бүрт хадгалах
- PO үүсгэхдээ хямд нийлүүлэгчийг автоматаар сонгох
- "Хүснэгтийг өөрчлөх" боломжтой

### 14. Барааны дүр зураг (Inventory Heatmap)

**Асуудал:** Агуулахын бодит байдлыг нэг хараар харах хэрэгтэй.

**Шийдэл:**
- Тавиар бүрийн зургийг татаж аваад дээр нь өнгөөр тэмдэглэх
- Ногоон = хангалттай, Шар = бага, Улаан = дууссан
- Асуудалтай хэсгийг шууд харж болно

## Анхаарах зүйлс

1. **Мобайлд тэргүүлэх** — бүх шинэ фичер утаснаа ажиллах ёстой. Механикууд компьютер ашиглахгүй.
2. **Хэтэрхий олон талбар нэмэхгүй** — нэг даралт = нэг үйлдэл зарчмыг баримтлах.
3. **Одооны системээ эвдэхгүй** — шинэ фичерүүд нэмэлт хэсэг болох ёстой, одооны UI-ийг өөрчлөхгүй.
4. **Монгол хэл дээр тэргүүлэх** — бүх label, tooltip, error message Монгол хэлтэй байх.
