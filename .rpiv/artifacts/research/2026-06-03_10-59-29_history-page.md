# Research: Түүх (History) sidebar page

## Research Question

How to implement a new "Түүх" sidebar page with 2 tabs (Invoices + Work Orders), each with DataTable + URL-synced filters, and right-side Sheet detail views for both data types, using existing codebase patterns.

## Summary

The codebase has well-established patterns for sidebar pages (DataTable + `useTableFilters` + `usePageHeader` + `_global-dialogs.tsx`). The History page can follow these exactly, with two additions: (1) new `detailInvoiceId`/`detailWorkOrderId` state in `usePageHeader`, and (2) a new invoice detail API route at `/api/organizations/[id]/invoices/[invoiceId]/`. Tab switching should use `usePageHeader`'s `setTabs`/`setActiveTab` to drive the PageHeader component's tab bar. Data fetching should use new React Query hooks (`useInvoices`, `useWorkOrderDetail`) following the `createOrgQuery` factory pattern. Detail sheets should use the `Sheet` component (right-side) like `ExpenseDetailSheet`, reusing shared sub-components from the bay-view drawer for work order details.

## Detailed Findings

### Navigation & i18n

- **Sidebar entry**: Insert into `src/hooks/use-navigation.ts` Operations group children array (around line 66), after `nav.workOrders`. Key: `"nav.history"`, href: `"/dashboard/history"`, icon: `LayoutGrid`.
- **Mechanic filter exception**: The mechanic role filter at `use-navigation.ts:286` removes `bay-view` from Operations group — `history` should NOT be filtered out (mechanics can see history).
- **i18n keys**: Add `"nav.history": "Түүх"` to `src/messages/mn.json` and `"nav.history": "History"` to `src/messages/en.json` following same pattern as other Operations children.
- **Breadcrumbs**: Add `"history": "nav.history"` to `SEGMENT_TO_NAV_KEY` in `src/hooks/use-breadcrumbs.ts:15`.

### DataTable Page Pattern (from work-orders, customers, expenses)

- Each sidebar page follows: `"use client"` → `useTableFilters("prefix")` → `usePageHeader()` → render `DataTable` with `columns`, `data`, `pageSize={20}`, `onRowClick`.
- `useTableFilters("history-invoices")` / `useTableFilters("history-orders")` — separate filter prefixes for each tab to prevent URL param conflicts.
- Two DataTable instances on one page is a new pattern — each needs its own `columns.tsx` file:
  - `src/app/[locale]/dashboard/history/_invoice-columns.tsx`
  - `src/app/[locale]/dashboard/history/_work-order-columns.tsx`
- `DataTable` (`src/components/ui/data-table.tsx:111`) accepts: `columns`, `data`, `pageSize`, `onRowClick`, `loading`, `totalCount`, `searchPlaceholder`.

### Data Fetching — React Query Hooks

- **New `useInvoices()` hook**: Following `useWorkOrders()` pattern at `src/lib/queries/use-work-orders.ts:17` using `createOrgQuery` factory (`src/lib/queries/factory.ts:30`).
- **New `useWorkOrderDetail(orgId, id)` hook**: For fetching single work order with full details (services, parts, status history). Should mirror `useExpense()` pattern at `src/lib/queries/use-expenses.ts:14`.
- **Existing `getInvoices()` service**: `src/lib/services/invoice-service.ts:40` — already supports `{ status }` filter.
- **Existing `getInvoice(id)` service**: `src/lib/services/invoice-service.ts:103` — fetches single invoice with items and payments. No Next.js API route exposes it yet.

### API Routes

- **List invoices**: **EXISTS** at `src/app/api/organizations/[id]/invoices/route.ts:9-14` — `GET` with optional `?status=` filter, delegates to `getInvoices()`.
- **Single invoice detail**: **MISSING** — needs new route at `src/app/api/organizations/[id]/invoices/[invoiceId]/route.ts` that calls `getInvoice(id)` and returns `InvoiceWithItems` (items + payments).
- **Update existing route**: The current `src/app/api/organizations/[id]/invoices/[invoiceId]/route.ts` exists but only handles `PATCH` and `DELETE` (no `GET`). Adding `GET` handler is simpler than creating a new file.
- **Work order detail**: Use existing work order API — `src/app/api/organizations/[id]/work-orders/[workOrderId]/route.ts` should have `GET` handler, or create one following the invoice pattern.

### Detail Sheet Wiring (usePageHeader + _global-dialogs.tsx)

- **New state pairs**: Add to `PageHeaderContextValue` (`src/hooks/use-page-header.tsx:28`):
  - `detailInvoiceId: string | null` / `setDetailInvoiceId`
  - `detailWorkOrderId: string | null` / `setDetailWorkOrderId`
- **Initialize in PageHeaderProvider** (around line 103): `useState<string | null>(null)` for both.
- **Wire in _global-dialogs.tsx**: Add lazy-loaded dynamic imports for:
  - `InvoiceDetailSheet` from `@/components/invoices/invoice-detail-sheet`
  - `WorkOrderDetailSheet` from `@/components/work-orders/work-order-detail-sheet`
- **Mount pattern** (follows `ExpenseDetailSheet` at line 87-91): `open={detailInvoiceId !== null}`, `onOpenChange={(open) => setDetailInvoiceId(open ? detailInvoiceId : null)}`, `invoiceId={detailInvoiceId}`.
- **onRowClick**: Set the detail ID — `onRowClick={(row) => setDetailInvoiceId(row.id)}` for invoices tab, same pattern for work orders.

### Detail Sheet Content

- **Component**: Use `Sheet` + `SheetContent side="right"` with `className="w-full sm:max-w-2xl p-0 gap-0"` — following `ExpenseDetailSheet` pattern at `src/components/expenses/expense-detail-sheet.tsx:147`.
- **Header**: Reuse `DetailSheetHeader` from `src/components/ui/detail-sheet-header.tsx:13` (accepts `icon`, `title`, `subtitle`, `actions`).
- **Invoice detail sheet**: Shows invoice info, items table, payment history, PDF preview link, print button.
- **Work order detail sheet**: Reuses bay-view drawer sub-components:
  - `StatusTimeline` from `src/components/bay-view-v2/_status-timeline.tsx`
  - `ServicesSection` from `src/components/bay-view-v2/_services-section.tsx`
  - `PartsSection` from `src/components/bay-view-v2/_parts-section.tsx`
  - `TotalsSummary` from `src/components/bay-view-v2/_totals-summary.tsx`
  - `NotesSection` from `src/components/bay-view-v2/_notes-section.tsx`
- **Invoice link in work order sheet**: If work order has linked invoice, show a "Баримт үзэх" button that opens the invoice tab or the invoice detail sheet.

### Tab Switching

- Use `usePageHeader`'s `setTabs`/`setActiveTab` — these drive the `PageHeader` component's tab bar at `src/components/page-header.tsx:30-35`.
- `setTabs([{ value: "invoices", label: "Баримтууд" }, { value: "orders", label: "Захиалгын түүх" }])` — renders a top tab bar.
- `activeTab` from context determines which DataTable is rendered.
- Tradeoff vs local state: using `usePageHeader` keeps the tab bar visually consistent with page header layout; local state (`useState`) is simpler but the tab bar would need manual positioning.

### Right Sidebar (useRightSidebar)

- NOT needed for History page. The right sidebar (`useRightSidebar`) is only rendered when `isBayView` is true in `src/app/[locale]/dashboard/layout.tsx:46`. History page relies solely on `usePageHeader` + `_global-dialogs.tsx` for all sheet state.

## Architecture Insights

1. **Tab + DataTable pattern**: No existing sidebar page has two tabs. The History page establishes a new pattern: `usePageHeader.setTabs()` to drive tab bar, derived state to pick which `useTableFilters` + `DataTable` renders.

2. **Sheet reuse over Drawer**: The codebase has two overlay patterns — Sheet (right-side, used by expense/customer/vehicle details) and Drawer (used by bay-view). The History page should use Sheet to match the majority of sidebar pages. Work order detail content (services, parts, timeline) is reusable from bay-view's `_`-prefixed sub-components.

3. **React Query for new code**: The trend in the codebase is toward React Query hooks (all recent sidebar pages). The finance page's manual `fetch()` is legacy. New code should use `createOrgQuery` factory hooks.

4. **Global dialog mounting**: All new sheets MUST be mounted in `_global-dialogs.tsx` and controlled via `usePageHeader` state — this is the enforced pattern. Bypassing it (mounting sheets locally in the page) is inconsistent with the dashboard architecture.
