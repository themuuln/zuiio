# Түүх (History) Sidebar Page — Implementation Plan

## Overview

Шинэ "Түүх" sidebar page-г Operations групп дор нэмэх, 2 tab-тай (Баримтууд + Захиалгын түүх), DataTable + URL-synced filters, right-side Sheet detail view-тэй. Одоо байгаа pattern-ийг дагана: `usePageHeader.setTabs()` + tab content компонентууд + `_global-dialogs.tsx`-ээр detail sheets холбох.

## Requirements

- Sidebar-т "Түүх" entry Operations групп дор нэмэгдэнэ
- 2 tab: Баримтууд (Invoices) + Захиалгын түүх (Work Orders)
- Tab бүр DataTable + шүүлтүүр (useTableFilters)
- Мөр дээр дарахад right-side Sheet нээгдэнэ
- Invoice detail sheet-д: invoice info, items, payment history, PDF preview
- Work order detail sheet-д: vehicle, services, parts, status timeline, invoice link
- React Query hooks (createOrgQuery factory)
- usePageHeader.setTabs() tab удирдлага

## Current State Analysis

- Invoice list API: ✅ `GET /api/organizations/[id]/invoices/` (with `?status=` filter)
- Invoice detail API: ✅ `GET /api/organizations/[id]/invoices/[invoiceId]` (returns InvoiceWithItems)
- Work order list API: ✅ exists
- No sidebar entry, no history page, no detail sheets for invoices/work-orders in global dialogs
- usePageHeader has no detailInvoiceId/detailWorkOrderId state yet

### Key Discoveries

- `src/app/api/organizations/[id]/invoices/[invoiceId]/route.ts` already has `GET` handler calling `getInvoice()` — no API gap
- `src/lib/queries/factory.ts:30` — `createOrgQuery` factory creates typed fetchers
- `src/components/expenses/expense-detail-sheet.tsx:147` — Sheet pattern template
- `src/app/[locale]/dashboard/finance/page.tsx:73-99` — TabBar pattern (usePageHeader alternative chosen)
- `src/components/bay-view-v2/_status-timeline.tsx` — reusable timeline for work order detail
- `src/components/bay-view-v2/_services-section.tsx`, `_parts-section.tsx` — reusable sub-components

## Desired End State

```tsx
// Navigation sidebar shows "Түүх" under Operations
// Page opens at /dashboard/history with 2 tabs + DataTable per tab
// Right-side sheet opens on row click with full detail
// Invoice sheet shows invoice info + items + payments + PDF link
// Work order sheet shows vehicle, services, parts, timeline, invoice badge
```

## What We're NOT Doing

- Not creating new API routes (all exist)
- Not building edit/create functionality (read-only history page)
- Not using right-sidebar (useRightSidebar) — only bay-view uses it
- Not using Drawer component — Sheet (right-side) is the chosen pattern
- Not modifying the finance page or its invoices tab

## Decisions

### Tab approach
**Ambiguity**: Tab switching — usePageHeader.setTabs vs local useState + TabBar
**Explored**: Option A (usePageHeader.setTabs) — PageHeader renders tab bar, `src/components/page-header.tsx:30-35`. Option B (local state + TabBar) — finance page pattern, `src/app/[locale]/dashboard/finance/page.tsx:73-99`.
**Decision**: usePageHeader.setTabs() — keeps tab bar consistent with dashboard layout.

### Data fetching
**Decision**: React Query hooks via createOrgQuery factory — `src/lib/queries/factory.ts:30`.

### Detail overlay
**Decision**: Right-side Sheet — `src/components/expenses/expense-detail-sheet.tsx:147` pattern.

### Tab content architecture
**Decision**: Each tab is a separate component file (`_invoices-tab.tsx`, `_work-orders-tab.tsx`) receiving scoped props.

## Performance Considerations

- DataTable uses built-in pagination (20 rows per page) — no client-side loading of all records
- React Query caching (staleTime: 15s) reduces re-fetches
- Lazy-loaded detail sheets via dynamic import — no code loaded until first open
- Filter state URL-synced — shareable/bookmarkable URLs
