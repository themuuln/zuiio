## Goal

The full game-log table is moved below the visual showcase sections, hidden behind a "Бүх тоглолт" tab. The default tab ("Тойм") shows the organized visual sections — hero card, milestones, charts, recent games.

## Why

The game-log table is long and data-dense — it was the entire page in Phase 1. With Phase 2 adding visual sections (hero card, season arc, shooting profile, radar, milestones, recent games), the table should be secondary: still available in one tap, but not dominating the page.

## Implementation Steps

1. **Page restructure**: the player page was already rendering the full game-log table at the bottom. Wrap the visual sections (hero card, milestones, season arc, shooting profile, radar, recent games) inside a `TabsContent value="overview"`. Wrap the existing game-log table inside `TabsContent value="all-games"`.
2. **Tabs component**: use shadcn `Tabs` with `TabsList` containing two triggers: "Тойм" (Overview, default) and "Бүх тоглолт" (All Games).
3. **Visual order**: within `Тойм` tab, the visual sections render in order: hero card → milestones → season arc → shooting profile → skill radar → recent games. Each section is a self-contained component.
4. **Game log table preserved**: the "Бүх тоглолт" tab renders the exact same game-log table that existed before — all columns, all rows, no changes. The table is intact.
5. **No scroll-to on tab switch**: switching tabs does not trigger scroll-to behavior — the user stays at the top of the new tab content.

## Design Decisions

- **Tabs, not accordion**: tabs keep both views one tap away without vertical scrolling and are more discoverable. Accordion forces the user to close/open sections.
- **Game log untouched**: the existing game-log table is preserved verbatim — no column changes, no filtering, no pagination changes. The only difference is its position in the tab.
- **Default tab = overview**: the first-time visitor sees the visual showcase, not the raw table. This is the core UX improvement of Phase 2.
- **Server Component tabs**: shadcn `Tabs` with `TabsContent` is used in a Server Component context — the content inside each tab is pre-rendered on the server. Tab switching just shows/hides.
- **Section order**: the visual sections are ordered to tell a story: hero (who) → milestones (achievements) → arc (trend) → shooting (style) → radar (profile) → recent games (current form). This is a deliberate narrative flow.

## Risks & Gotchas

- **Tab overflow on mobile**: with two tab triggers ("Тойм", "Бүх тоглолт"), the tab bar is short enough to fit on any screen. If more tabs are added later, use `TabsList` with responsive wrapping.
- **Page height**: the visual sections plus the (now hidden) game log mean the page is shorter at first load — intentional, but verify that the page still scrolls naturally.
- **Tab default state**: `Tabs` requires a `defaultValue` prop. Set to `"overview"` to ensure the showcase is the default view.
- **Shadcn Tabs styling**: the tabs component may need custom CSS for the active indicator to match the app's brand colors.
