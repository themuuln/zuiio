## Goal

A printed procedure and scoresheet for when tech fails. The runbook covers pre-game checklist, during-game failure ladder (app crash → reload/replay; device dead → handoff; network dead → keep tracking offline; all dead → paper sheet), and post-game flow. The printable scoresheet at `/tracker/paper` renders rosters + period score grid + per-player tally rows in A4 portrait format.

## Why

The tracker must work when everything goes wrong — network drops, device dies, app crashes. Without a documented procedure, scorers panic and the game's stat record is lost. The paper scoresheet is the ultimate fallback: when no digital path works, paper keeps the game record accurate. Every subsequent scorer training session references this runbook.

     1. App crash / tab killed → reopen, verify count, cross-check paper

## Design Decisions

- **Runbook is human-first, not agent-oriented**: written for Mongolian basketball volunteers who may not be technical. Clear step-by-step procedures, Mongolian copy, printed on paper and kept courtside.
- **Paper scoresheet is a static template, not data-driven**: no API calls, no authentication, no dynamic roster loading. The scorer fills in team names and player names by hand. This ensures the paper page always works even when the database is unreachable.
- **Print CSS not a library**: uses Tailwind `print:` utility variants only. No `@media print` overrides in custom CSS — keeps it simple and avoids print-specific bugs.
- **Error code reference in runbook**: each error code documented with meaning and action so scorers can self-diagnose during a game without asking an admin.
- **Player takedown procedure included**: even though T-2.2 (Consent & takedown) is Phase 2, the runbook includes a forward-reference to the admin procedure. Update when T-2.2 is complete.

## Risks & Gotchas

- **Runbook must stay in sync with features**: as new features are added (ops console, integration tests, Phase 2+ surfaces), the runbook must be updated. Add a "Last reviewed" date and establish a review cadence (every phase completion).
- **Paper scoresheet assumes 5x5 ruleset**: if the game uses a different ruleset (3x3, youth), the stat categories on the paper sheet may not match. Consider making the paper page read the game's ruleset and rendering the appropriate stat categories.
- **Print rendering differences**: A4 may render differently in Chrome vs Safari vs Firefox. Test print layout across browsers. Safari in particular has inconsistent handling of `@page` size and print margins.
- **Mongolian text orientation**: Mongolian can be written vertically in traditional script. The scoresheet uses Cyrillic Mongolian (horizontal), which is standard for modern Mongolian basketball.
- **The runbook assumes the tracker flows exist**: if the handoff dialog (T-1.7) or admin review UI (T-1.3) have UX changes after the runbook is written, the runbook's handoff procedure and post-game flow sections need updating.
