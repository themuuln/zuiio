## Goal

Game-by-game PTS / REB / AST trend as an interactive area chart, with stat toggles and tooltip details.

## Why

The season arc gives immediate visual sense of a player's trajectory — hot streaks, cold spells, injury returns. A table of game logs buries this signal in rows; a chart reveals it in one glance.

## Implementation Steps

1. **Install chart library**: `pnpm dlx shadcn@latest add chart` — adds Recharts as dependency + creates `src/components/ui/chart.tsx` with `ChartContainer`, `ChartTooltip`, `ChartTooltipContent`.
2. **Data helper**: `getPlayerGameLog(playerId, competitionId)` in `src/app/lib/data.ts` — queries `v_public_box_score` joined to `v_public_games` for date, opponent, pts, reb (oreb + dreb), ast. Orders by game date ascending. Returns typed `PlayerGameLine[]`.
3. **`SeasonArc` client component**: `"use client"`, wraps `ChartContainer` + Recharts `AreaChart`. Main area series = PTS. Two toggleable line series = REB, AST. Toggle via shadcn `Tabs` above the chart. Tooltip shows opponent + date via `ChartTooltipContent`. X-axis uses game index (not dates) with the actual date in the tooltip.
4. **Empty / low-data state**: if `data.length < 2`, render the recent-games strip message ("Хангалттай тоглолтын өгөгдөл байхгүй") instead of a degenerate chart.
5. **Lazy load**: import through `chart-sections.tsx` `dynamic()` wrapper so Recharts (~1.5MB) isn't loaded for non-chart pages.
6. **Integrate into player page**: render after hero card under a "Улирлын замнал" section heading with scroll-reveal animation.

## Design Decisions

- **Area for PTS, lines for REB/AST**: area fill creates visual weight for the primary stat (PPG). Lines keep the secondary stats readable without occlusion. The pattern matches how sportscasters present scoring trends.
- **Game index on X-axis, date in tooltip**: dates are often unevenly spaced (breaks between games) — using index keeps the visual spacing uniform. The actual date is one hover away.
- **Tab toggle (not checkbox)**: shadcn `Tabs` is semantically clearer than checkboxes and matches the app's existing tab patterns.
- **Cold-start empty state**: fewer than 2 games gets a centered message rather than a blank chart — follows the "cold-start" convention from the design system.

## Risks & Gotchas

- **Chart height at mobile**: at 360px, `ChartContainer` needs an explicit `h-[200px]` and responsive padding to avoid overflow. The chart config uses `aspectRatio` or height prop.
- **Tooltip positioning**: on small screens, the tooltip may overflow the viewport. Recharts `ChartTooltipContent` should handle this with `side="top"` or responsive positioning.
- **Dynamic import timing**: the `dynamic()` import with `{ ssr: false }` prevents hydration errors but means the chart flashes on mount — this is acceptable for a below-fold chart.
- **Brush for long seasons**: if a player has 40+ games, consider adding Recharts `<Brush />` for panning. Currently not implemented — add if UX testing shows it's needed.
