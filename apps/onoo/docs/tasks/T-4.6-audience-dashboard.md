## Goal

Proof-of-audience numbers for sponsor pitches.

## Why

Sponsors need audience data to justify investment. An audience dashboard with daily page view counts across entity types (players, games, teams, home) provides verifiable engagement metrics for sponsor proposals and tier pricing.

## Implementation Steps

### Database Layer

1. **Migration:**
   - Table `daily_page_views (day date not null, entity_type text not null check (entity_type in ('player','game','team','home','leaders','standings')), entity_id uuid, views bigint not null default 0, primary key (day, entity_type, entity_id))`
   - Function `cmd_increment_page_view(p_entity_type text, p_entity_id uuid)` SECURITY DEFINER doing `INSERT ... ON CONFLICT (day, entity_type, entity_id) DO UPDATE SET views = views + 1` for today's date
   - RLS: table closed to public
   - `GRANT EXECUTE ON FUNCTION cmd_increment_page_view TO anon`

### Tracking Layer

2. **`ViewBeacon` component:** Create `view-beacon.tsx`:
   - Client component. Props: `entityType`, `entityId?`
   - Fires one `navigator.sendBeacon('/api/track', body)` per mount
   - Guard with `useEffect` + `useRef` once-flag — fires exactly once
   - Skip when `document.visibilityState === 'prerender'` (prevents prerender false counts)
   - **No cookies, no IP storage, no user agent** — pure count, privacy-safe

3. **Track API route** `src/app/api/track/route.ts`:
   - POST handler: parses `entityType` + `entityId` from body
   - Calls `cmd_increment_page_view`
   - Returns 204 No Content
   - Lightweight — no logging, no analytics processing

4. **Mount beacons:**
   - Player page (`/players/[id]`): entity_type='player', entity_id=player.id
   - Game page (`/games/[id]`): entity_type='game', entity_id=game.id
   - Team page (`/teams/[slug]`): entity_type='team', entity_id=team.id
   - Homepage: entity_type='home', use fixed zero-uuid `00000000-0000-0000-0000-000000000000`
   - Leaders page: entity_type='leaders', zero-uuid
   - Standings page: entity_type='standings', zero-uuid

### Admin Dashboard

5. **Audience dashboard** `src/app/admin/audience/page.tsx`:
   - Auth guard: `supabase.auth.getUser()` → 401
   - Date range picker (default last 30 days)
   - Summary totals per entity_type
   - Top-10 most-viewed players (join names)
   - Top-10 most-viewed games (join metadata)
   - One Recharts line chart of daily totals over the selected range
   - Add a note: this page is independent from the ops console — "audience and ops pages serve different buyers"

## Design Decisions

- `sendBeacon` is preferred over `fetch` for tracking — it's fire-and-forget, doesn't delay page unload, and works even when the page is being closed.
- Once-flag via `useRef<boolean>` prevents double-counting from React Strict Mode's double-mount in development.
- No user identifiers: no cookies, no IP logging, no user-agent parsing — purely aggregate counts for privacy compliance.
- Entity types are string enums (checked at DB level) for readable queries. Zero-uuid for homepage/leaders/standings which have no single entity ID.
- Audience dashboard is separate from ops console — they serve different stakeholders and shouldn't be conflated.

## Risks & Gotchas

- `cmd_increment_page_view` must be granted to `anon` role — otherwise public pages can't call it. Verify the grant is correct.
- React Strict Mode mounts components twice in development, but the `useRef` once-flag prevents double-fires even in dev.
- `sendBeacon` sends a POST with `Content-Type: text/plain` by default. The API route should accept `text/plain` bodies (parse as JSON) or the beacon should explicitly set content type (via Blob).
- Fixed zero-uuid for entity-less pages: use the actual `00000000-0000-0000-0000-000000000000` value — it's a valid UUID for grouping.
- The daily totals line chart aggregates across all entity_types — show a total line plus per-type colored lines as legend.
