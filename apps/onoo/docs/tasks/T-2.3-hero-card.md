## Goal

Top of the player page reads like a trading card — avatar, name, jersey, position, team chip, and animated stat numbers (PPG, RPG, APG) with team color accent.

## Why

The hero card is the first thing visitors see on a player page. It establishes visual identity, delivers key season averages at a glance, and sets the design tone for the entire profile. Without it, the page starts with raw data.

## Data Dependencies

| Entity | Access | Purpose |
|--------|--------|---------|
| `getPlayerById(id)` | Read | Player bio (name, jersey, position, team, photo, height, weight, DOB, nationality) |

## Implementation Steps

1. **Data layer**: add `getPlayerSeasonAverages(playerId, competitionId)` to `src/app/lib/data.ts` — queries `v_public_leaders` for the player's per-game averages.
2. **Count-up hook**: `useCountUp(target, {duration: 800})` — rAF-based animation from 0 to target with ease-out cubic easing; respects `prefers-reduced-motion` by jumping straight to target.
3. **`StatNumber` client component**: renders animated value + label; shows em-dash (`–`) for null values (zero-game players). Supports size variants `sm|md|lg|xl` and accent color.
4. **`FlipStatCard`**: interactive card that flips on click (CSS 3D transform front/back) — front shows the stat value, back shows league rank (e.g., "#2 in league").
5. **`HeroCard` Server Component**: layout — `PlayerAvatar xl` (left), name + jersey `#` + position + team chip (right), 3–5 stat columns below (PPG, RPG, APG + SPG, BPG at ≥sm). Sets `--team-color` CSS variable for accent. Fetches bio + averages + leaders in parallel.
6. **Integrate into player page**: render `<HeroCard>` at the top of the player page, wrapped in `<ScrollReveal>` for entrance animation. Pass `competitionId` from search params or default competition.
7. **Cold-start handling**: players with zero games show em-dash for all stats, no animation.

## Design Decisions

- **Server-first**: `HeroCard` is a Server Component; only `StatNumber` and `FlipStatCard` are client components (for animation and interaction). Minimizes client bundle.
- **Team color accent only**: `--team-color` is used for decorative accents (borders, gradient undertones) — text stays on neutral background for contrast/accessibility.
- **Rank computation**: ranks computed client-side-ish (actually in the Server Component) by sorting the leaders array for each stat. This is O(n) per stat and the leaders array is small (~50 players), so fine for server.
- **FlipStatCard**: CSS 3D transform rather than a state-heavy animation library — lightweight, accessible (focusable button with `aria-label`).
- **Stat selection**: PPG, RPG, APG always visible; SPG, BPG added at `≥sm` breakpoint via responsive CSS.

## Risks & Gotchas

- **Null averages**: `getPlayerSeasonAverages` returns `null` when player has no games in the competition. The hero card must handle this without crashing — checks `averages?.pts` etc.
- **Competition ID**: if `competitionId` is null (e.g., career mode), the hero card should fall back to career totals or skip rank display.
- **Animation on re-render**: when switching seasons via the season selector, the hero card re-renders with new averages. `StatNumber` restarts its count-up animation because `target` changes — this is intentional and feels good.
- **Contrast on color**: primary_color could be very light or very dark. The hero card uses color only for borders/accents, never for text backgrounds, so contrast is maintained.
