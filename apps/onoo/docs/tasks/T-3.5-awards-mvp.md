## Goal

Weekly/season recognition the league grants and players share.

## Why

Awards (Player of the Week, MVP, Top Scorer) create a recognition loop — players share awards socially, leagues build legitimacy, and the MVP race drives recurring engagement throughout the season.

## Design Decisions

- EFF weights (`+1.5 ast, +2 stl, +2 blk`) are stored as a `const EFF_WEIGHTS` in `packages/core/src/lib/stats.ts` with a comment explaining the Mongolian league tuning: assists are weighted slightly higher than NBA EFF because Mongolian offenses are more assist-dependent; steals and blocks weighted at 2x for defensive impact.
- MVP race is computed on read (not stored) so it updates automatically with every game — no manual recalculation needed.
- Admin guard follows the established `user_can_approve_game` pattern — check that function's implementation for the secret/role pattern to replicate.

## Risks & Gotchas

- `cmd_grant_award` must verify the caller has admin privileges. Follow the existing `user_can_approve_game` guard exactly — don't invent a new authorization mechanism.
- EFF formula constants are in one place with rationale comment — if someone wants to change weights later, they know where and why.
- The MVP race card shows "rank deltas omitted" — don't try to compute week-over-week deltas; that's future work. Just show current rank number.
- Seeded data: need at least 5 qualified players with enough games in the same competition to test the MVP race.
