## Goal

Final score, top performers, lead flow — visual.

## Why

A finished game recap is the most-shared piece of content after a game. A visual recap with top performers, lead flow chart, and clear final status turns a box score into a story that fans can share and discuss.

## Implementation Steps

1. **Determine recap availability:** Recap section renders only when game status is `final_pending_review`, `league_verified`, or `official`. If game is `scheduled` or `live_provisional`, do not render recap at all.
   - Provisional visibility (status `final_pending_review`): renders with "Урьдчилсан дүн" badge — this requires Task 5.1's `v_public_live_games` view. If 5.1 hasn't landed, recap covers verified+official only and include a `TODO(5.1)` comment.

2. **`RecapHeader` component:** Create `recap-header.tsx`:
   - Score displayed large and centered
   - Status chip: `final_pending_review` → "Урьдчилсан дүн" (amber), verified → "Баталгаажсан" (green)
   - Team logos + names
   - Date and venue

3. **`TopPerformers` component:** Create `top-performers.tsx`:
   - Top-3 players from the game ranked by EFF (same formula constant as T-3.5 — import from `@onoo/core`, don't redefine)
   - Each as a card: `PlayerAvatar`, name, team, stat line (PTS/REB/AST), one-liner from `describePlayerGame`
   - Links to player pages
   - Responsive: stacks on mobile, side-by-side on desktop

4. **`ScoreWorm` component:** Create `score-worm.tsx` (client component, Recharts):
   - `AreaChart` of cumulative score differential over event sequence from play-by-play
   - Centered around zero: positive = home team leading, negative = away team leading
   - Team-colored fill under the line (home color for above-zero, away color for below-zero)
   - Quarter/period boundaries as reference lines (vertical dashed)
   - X-axis: event sequence number or time, Y-axis: point differential
   - `"use client"` — Recharts requires client-side rendering

5. **Wire to game transition:** Verify the recap page renders correctly the moment `cmd_transition_game` moves a game to `final_pending_review`. Use the integration script from Task 1.10 to test this transition flow.

## Design Decisions

- EFF constant imported from shared location (packages/core) — single source of truth shared with T-3.5 MVP race. Never redefine.
- Score worm uses `AreaChart` not `LineChart` — area fill emphasizes which team is leading and by how much.
- Reference lines for quarter boundaries improve readability of the game flow story.
- Top performers use the same card component pattern as the roster grid (T-3.7) for visual consistency.

## Risks & Gotchas

- Play-by-play data must exist for the score worm. If no play-by-play exists, show a "Тоглолтын мэдээлэл бүрэн гүйцэд ороогүй" (Game data incomplete) message instead of a broken chart.
- `getPlayByPlay` exists in `data.ts` — verify its return shape before building the worm. It must include event sequence, score delta, and quarter info.
- Score differential computation: each event changes the score. The worm computes cumulative differential per event (home_score - away_score). Verify against known game data.
- If 5.1 hasn't landed, the `final_pending_review` games won't be visible through `v_public_games`. The TODO comment marks the gate clearly.
