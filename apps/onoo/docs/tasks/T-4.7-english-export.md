## Goal

Scout-facing English toggle + export.

## Why

Mongolian basketball has international scouting interest. An English language toggle on player pages (with Latin name transcription and English stat labels) makes profiles accessible to foreign scouts and journalists. A PDF export provides a shareable offline document.

## Implementation Steps

1. **Locale toggle component:** Create `lang-toggle.tsx`:
   - A simple `<Link>` element — server-rendered, no client state
   - Current locale → toggle link: if current is `mn`, link to `?lang=en`; if `en`, link to `?lang=mn` (or plain URL)
   - Label: "EN" / "MN"
   - Only mounted on player page — not in nav/layout

2. **Player page locale support:** Update `players/[id]/page.tsx`:
   - Read `searchParams.lang` from page props
   - Pass locale through to all data display helpers:
     - `formatPlayerName(nameLatin, canonicalName, locale)` — for EN, prefers `name_latin`
     - `getStatLabel(stat, locale)` — for EN, uses `en` dictionary
     - Date formatting: `en-US` format when `lang=en`
     - Milestone/summary strings: use EN variants from T-2.6 and T-2.9
   - Mount `LangToggle` component in the page header
   - Default is `mn` — no toggle, no override

3. **Verify i18n completeness:** Grep `packages/core/src/i18n/stats.ts` for the `en` dictionary. Fill any missing stat keys that the player page renders. Never use inline English strings — always go through the dictionary.

4. **PDF export endpoint:** Create `src/app/api/export/pdf/route.ts`:
   - Accepts `POST { playerId, lang? }`
   - Returns a PDF document (use a simple HTML→PDF approach or a PDF library — check what's available; if nothing is pre-installed, keep it simple with a printable HTML page styled for A4)
   - English header: "Official player statistics — Onoo" + competition name
   - Player stats in tabular format, locale-aware
   - **Do NOT add a new PDF library without approval** — use `@vercel/og` `ImageResponse` for a stat sheet image as a lightweight alternative, or just a print-styled HTML page with `window.print()` guidance

## Design Decisions

- Locale toggle is a simple `<Link>` with `searchParams` — no client i18n framework, no context providers, no state. Pure server-rendered navigation.
- Only player page gets the toggle. Site-wide EN mode is explicitly out of scope — this avoids duplicating every page's copy.
- PDF is lightweight: either a printable A4 HTML page or a generated image. No heavy PDF library without approval.
- Missing EN dictionary keys are filled in `stats.ts` — never inline English strings in components.

## Risks & Gotchas

- The `en` dictionary in `packages/core/src/i18n/stats.ts` may have gaps. The task must fill those gaps — grep the component's used stat keys against the dictionary.
- `formatPlayerName` with locale support: verify the function signature and whether it already handles `en` → `name_latin` preference. If not, extend it.
- Date formatting in `en-US`: `date-fns` `format(date, 'MMM d, yyyy', { locale: enUS })` — import `enUS` from `date-fns/locale`.
- The PDF export route may need to handle Cyrillic font embedding for the (optional) Mongolian version. For English-only, standard fonts suffice.
- Verify that the EN toggle does NOT persist across page navigations via localStorage/URL persistence — each navigation resets to MN unless `?lang=en` is explicitly added.
