## Goal

Podiums, not table rows.

## Why

A podium layout makes league leaders visually iconic and instantly readable — the top-3 get hero treatment while ranks 4–10 remain accessible. This drives shares and makes the leaders page a destination.

## Files to Touch

```
- src/app/leaders/page.tsx                      — restructure to use podium + rows
- src/app/leaders/components/leader-tabs.tsx    — extend to support server-driven tab linking
- src/app/leaders/components/podium.tsx         — NEW: top-3 podium cards
- src/app/leaders/components/leader-row.tsx     — NEW: compact row for ranks 4–10
```

## Data Dependencies

| Entity | Access | Purpose |
|--------|--------|---------|

## Implementation Steps

1. **Audit existing page:** Read current `src/app/leaders/page.tsx` and `leader-tabs.tsx` to understand existing fetch pattern and tab state. Leader tabs already exist but may use client state — this task keeps them server-driven.

2. **`Podium` component:** Create `podium.tsx`:
   - Rank 1 (center): larger `PlayerAvatar`, big per-game number (e.g. "32.5"), team chip
   - Rank 2 (left) and Rank 3 (right): slightly smaller
   - Gold/silver/bronze accent colors for ranks
   - All entries link to player pages (`/players/[id]`)
   - Responsive: podium collapses gracefully at 360px (stacked or smaller)

3. **`LeaderRow` component:** Create `leader-row.tsx`:
   - Compact row: rank number, `PlayerAvatar` (small), name, team `short_code`, stat value
   - All entries link to player pages
   - Zebra or alternating background

4. **Leader tabs:** Ensure the existing `leader-tabs.tsx` renders `<Link>` elements with `searchParams` style (`?stat=pts`) so the page stays a Server Component. No client state for tab selection. Extend the tab set to include: PTS, REB, AST, STL, BLK per game.

5. **Page restructure:** Replace flat table in `leaders/page.tsx` with: stat tabs at top → podium for top-3 → compact row list for ranks 4–10. The page reads `searchParams.stat` to determine active stat and passes it to `getLeaders()`.

## Design Decisions

- Server-driven tabs via `searchParams` — no client state, keeps page as Server Component, enables proper shareable URLs for each tab.
- Podium uses gold (#FFD700) / silver (#C0C0C0) / bronze (#CD7F32) accent colors via CSS variables.
- Per-game stat labels use `STAT_LABELS` from `@onoo/core` — already has Mongolian translations.
- PlayerAvatar from T-2.1 can accept a size prop (`sm`, `md`, `lg`) to control podium sizing.

## Risks & Gotchas

- Tab navigation is a full page navigation (server-rendered). Confirm that scroll position is reasonably maintained — if not, add `scroll={false}` to Link or a `layout` effect. The spec allows "≤ minor jump."
- `getLeaders` must support the `qualified = true` filter (Task 3.4 adds this). If 3.4 hasn't landed, `getLeaders` works without the param and shows all players.
- Player photos can be null — use the placeholder from Task 2.1 in that case.
