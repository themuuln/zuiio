## Goal

No path outside `cmd_*` commands can write to protected tables. All existing direct `.insert()`, `.update()`, `.upsert()` calls on protected tables are replaced with RPC calls or removed. The `manual-box-entry` Edge Function is deleted.

## Why

The entire trusted data foundation relies on every mutation going through a scoped `cmd_*` Postgres function that validates inputs, checks authorization, and logs to `audit_log`. Any code path that bypasses this layer creates a loophole: events can be written without ruleset validation, projections can be corrupted, and the audit trail is incomplete. Finding and closing these paths is the final step in hardening the data layer before the paid pilot.

## Design Decisions

- **Import route creates submissions, not direct writes**: this means imported data goes through the same review pipeline as any other source. Admins review and approve before the data becomes public. This is slower (not instant) but safer — no data enters the public surface without review.
- **Delete `manual-box-entry`**, don't deprecate: maintaining backward compatibility for a deprecated function that directly writes protected tables undermines the authorization model. Clean cutover.
- **Explicit `REVOKE` over implicit RLS**: RLS may already block writes from `authenticated`/`anon`, but making the REVOKE explicit documents the intent and provides a clear error message if a future migration introduces a new write path. Check current grants first with `\dp` to avoid redundant revocations.
- **Protected table list is documented in conventions**: the convention doc at `docs/plans/00-conventions.md` lists protected tables. Keep this list in sync with the migration and the sweep.

## Risks & Gotchas

- **Import route consumers**: there may be external scripts or cron jobs that POST to `/api/import` and expect instant writes. After this change, imported data needs admin approval before appearing in stats. Communicate this to the league ops team.
- **`manual-box-entry` in deployed Supabase**: the Edge Function may be currently deployed to the Supabase project. After deleting the local directory, also delete it from the hosted project via `supabase functions delete manual-box-entry` or the Supabase MCP `delete_edge_function` tool.
- **False positives in the sweep**: `.insert()` on tables like `source_submissions`, `audit_log` (via `write_audit`), and `error_reports` are legitimate and should be marked as justified. Don't block on these.
- **`\dp` output may differ between local and hosted**: run `\dp` against both environments to confirm. The migration should match the local state (after `supabase db reset` applies all migrations) — the hosted project may drift.
- **After REVOKE, the `cmd_*` functions (which use `SECURITY DEFINER`) must still work**: confirm that `SECURITY DEFINER` bypasses the table-level `REVOKE`. This is standard Postgres behavior, but verify with a test: call a `cmd_*` function as `authenticated` and confirm it succeeds.
