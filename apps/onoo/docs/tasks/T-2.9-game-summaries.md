## Goal

Auto-generated one-liners describing a player's game performance, in Mongolian and English, covering career highs, triple-doubles, double-doubles, 20+ point games, and default stat lines.

## Why

Plain-language summaries make stats accessible to family members and casual fans who don't immediately parse "15 pts, 8 reb, 6 ast" — the summary "15 оноо, 8 самбар, 6 дамжуулалт" is instantly understood. They're also reused in game recaps (Phase 4).

## Implementation Steps

1. **Core types**: define `GameSummaryInput` (pts, reb, ast, stl, blk, fgm, fga, tpm, ftm, isCareerHigh?, isSeasonHigh?, teamWon?) and `GameSummary` (`{ mn: string, en: string }`) in `packages/core/src/i18n/summaries.ts`.
2. **`describePlayerGame` pure function**: first-match-wins rule chain:
   - Career high → "Карьерийн дээд амжилт: X оноо" / "Career high: X pts"
   - Season high → "Улирлын дээд амжилт: X оноо" / "Season high: X pts"
   - Triple-double → detect via `countDoubles() ≥ 3`, generate "Гурван-X: X оноо, Y самбар, Z дамжуулалт"
   - Double-double → detect via `countDoubles() ≥ 2`, generate "Давхар-X: X оноо, Y самбар"
   - 20+ pts → "X оноо"
   - Team-high pts → "Багийн манлай: X оноо" (when teamWon and pts is clearly team-leading)
   - Default → "X оноо, Y самбар, Z дамжуулалт"
3. **Shooting suffix**: when `fga ≥ 10` and `fg% ≥ 60%`, append e.g., "60% пүршилттэй". Uses correct Mongolian basketball terminology from existing `STAT_LABELS` dictionary.
4. **`doubleDoubleLabel` helper**: given a game line with ≥2 stats at 10+, picks the two highest and returns display labels with values. E.g., "15 оноо, 12 самбар".
5. **Unit tests**: cover every rule boundary — career high (priority), season high, triple-double, double-double, 20+ pts, default, shooting suffix inclusion/exclusion. Test both Mongolian and English output. 190-line test suite.
6. **Application wrapper**: `src/app/lib/summaries.ts` — `generatePlayerGameSummary()` bridges the core function with the app's data types, computing `isCareerHigh`/`isSeasonHigh` flags from the player's game log context.
7. **Integration**: `RecentGames` component calls `generatePlayerGameSummary()` for each recent game and displays the `.mn` string as the card subtitle.

## Design Decisions

- **Pure function in core package**: `describePlayerGame` has zero I/O dependencies — it's a pure function that takes numbers and returns strings. Testable in isolation, usable from any context.
- **First-match-wins rule chain**: career high > season high > triple-double > double-double > 20+ > team-high > default. This ensures the most notable achievement is always the headline.
- **Separate `generatePlayerGameSummary` wrapper in app**: the core function is stateless and takes explicit `isCareerHigh`/`isSeasonHigh` booleans. The app wrapper computes those flags from the full game log context (using the milestone detector).
- **Shooting suffix as comma-separated append**: "X оноо, Y самбар, Z дамжуулалт, 60% пүршилттэй" — the comma-separated append avoids grammatical complexity in Mongolian.
- **Mongolian basketball terminology**: uses terms from `STAT_LABELS` dictionary. If a new term is needed (e.g., "пүршилт"), it's added to the dictionary, not invented inline.

## Risks & Gotchas

- **Double-double label ambiguity**: when a player has 10+ in 3 stats (e.g., 15 pts, 10 reb, 11 ast) but no triple-double trigger, the label must pick the two highest non-pts stats. The `doubleDoubleLabel` helper handles this with a priority: AST > REB > STL > BLK when values tie.
- **Mongolian pluralization**: numbers are followed by the singular noun form in Mongolian (unlike English). E.g., "15 оноо" (not "15 оноонууд"). Verify with native speaker.
- **Shooting suffix on multi-game contexts**: the summary is per-game, so career highs and shooting efficiency are computed per-game, not per-season.
