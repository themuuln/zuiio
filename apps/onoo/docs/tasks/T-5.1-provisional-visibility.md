## Goal

Live and just-finished games are publicly visible with an explicit provisional marker.

## Why

Today `v_public_games` exposes only `league_verified|official` games. This makes live scores and <5-minute recaps impossible. Provisional visibility is deliberately designed — it is not a leak, it's an intentional feature that makes the site feel alive during and immediately after games.

## Implementation Steps

### Database Layer

1. **Inspect existing schema:** Read `20260712010000_paid_pilot_publication.sql` to understand how live scores are tracked and projected. Determine if live score lives in `stat_events` (made-shot events) or has its own column in `games`.

2. **Migration — `v_public_live_games`:**
   - `CREATE VIEW v_public_live_games AS`
   - Games with status IN (`scheduled`, `live_provisional`, `final_pending_review`)
   - All columns that `v_public_games` exposes plus:
     - `is_provisional boolean` — `true` when status <> 'scheduled'
     - If live score comes from `stat_events`, aggregate made-shot events for the game to compute current score. If it's a column on `games`, expose it directly.
   - **Never** expose event-level provenance, submitter identity, or hidden-player names (mask per T-2.2 pattern)

3. **Update helpers in `data.ts`:**
   - `getLiveGames()`: query both `v_public_games` (any verified live games) and `v_public_live_games` (provisional statuses), merge with `is_provisional` boolean
   - `getGamesByDate()`: same dual-source approach, return merged with `is_provisional` flag
   - Both return typed results with the `is_provisional` flag included

### UI Layer

4. **Provisional badge component/logic:**
   - `GameCard`: when `is_provisional` is true, render an amber "Урьдчилсан" badge on the card
   - `LiveScoreCard`: same — amber badge
   - Game page header: if `is_provisional`, show amber badge next to the status
   - Recap header (T-4.3): remove the `TODO(5.1)` gate comment. Provisional games now render with "Урьдчилсан дүн" badge
   - `scheduled` games show no score (time only, no badge needed)

5. **Scheduled games display:**
   - Show start time, not score
   - No badge — scheduled games are not "provisional" even though they come through the same view

## Design Decisions

- Dual-source approach: `v_public_games` for verified+official + `v_public_live_games` for everything else. This keeps the verified view unchanged and adds the new view as a complement.
- `is_provisional` is computed as `status <> 'scheduled'` — scheduled games are not provisional, they're just upcoming.
- Amber badge color (`bg-amber-500` or similar) differentiates from green "Баталгаажсан" (verified) and red "LIVE" — visually distinct meaning "take this with a grain of salt."
- No event-level data exposed — only aggregated scores. The view is public-safe by design.
- Play-by-play data remains gated by `v_public_games` until it's available in the recap view (T-4.3).

## Risks & Gotchas

- Live score source: if it's in `stat_events`, aggregate `value_numeric` for `event_type = 'made_shot'` grouped by team. If it's a column on `games`, expose it directly. Inspect the existing schema before coding.
- Hidden player masking: the view must join player info and apply the T-2.2 visibility filter. If a hidden player scored all points, their stats are still part of the team total but their name is masked.
- `v_public_live_games` must be a proper superset of `v_public_games` columns (for the statuses it covers) plus `is_provisional`. Verify column compatibility.
- The role-matrix script (from Phase 1) tests that anon can select the new view but nothing else. Run it after migration.
