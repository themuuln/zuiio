## Goal

Any player/team reachable in two taps from anywhere.

## Why

Without search, users must know URLs or navigate through multiple pages to find a specific player or team. A keyboard-accessible command palette makes the entire league catalog browsable instantly from any page.

## Implementation Steps

### Database Layer

1. **Migration — `v_public_players`:** Create a view with:
   - `id, canonical_name, name_latin, photo_url, current_team_id, current_team_short_code`
   - Visibility-filtered per T-2.2 (hidden players excluded)
   - Only includes players with active team association

### API Layer

2. **Search helper** in `data.ts`: Create `searchPlayers(q: string)` that searches both `canonical_name` and `name_latin` with `ilike` for Cyrillic + Latin support. Create `searchTeams(q: string)` searching team `name` and `short_code`.

3. **Search API route:** Create `src/app/api/search/route.ts`:
   - `GET /api/search?q=` — minimum 2 characters
   - Returns up to 8 players + up to 4 teams
   - Response shape: `{ players: [...], teams: [...] }`
   - Public-safe: only returns visible players per `v_public_players`

### UI Layer

4. **`SearchCommand` component:** Create `search-command.tsx`:
   - shadcn `Dialog` (already available) opened via search button + `Cmd/Ctrl+K` keyboard shortcut
   - Input field with 250ms debounce via TanStack Query
   - Results sectioned: "Тоглогчид" (Players) with avatars + "Багууд" (Teams)
   - Enter key navigates to first result
   - Empty state: "Илэрц олдсонгүй" (No results found)
   - Loading state: spinner during debounce/delay
   - Error state: "Хайлт амжилтгүй" with retry

5. **Mount in layout:** Find the shared header/nav location in `src/app/layout.tsx` (or its imported nav component). Add the search trigger (magnifying glass icon button) to the nav bar. Mount the `SearchCommand` dialog component.

## Design Decisions

- Debounce via TanStack Query's built-in `enabled` + `staleTime` pattern (delay the query until user stops typing) rather than a manual setTimeout. TanStack Query v5 handles debounce naturally with `enabled: q.length >= 2` and the query function not running until enabled.
- Both Cyrillic and Latin name search uses `ilike` on both columns — covers Mongolian Cyrillic names and Latin transcriptions.
- Dialog component from shadcn (already installed) provides accessible modal behavior including focus trap and keyboard dismissal.
- Search is server-side via API route, not client-side filtering — handles large datasets efficiently.

## Risks & Gotchas

- The `v_public_players` view must JOIN with a visibility check. If T-2.2 uses a `consent_status` column or `hidden` flag, filter accordingly. If T-2.2 hasn't landed yet, the view initially shows all players and gets filtered later — leave a `TODO(2.2)`.
- Team search: teams don't have a visibility restriction (they're always public) but are limited to 4 results for performance.
- Keyboard shortcut: must not interfere with browser-native `Cmd+K` (which is bookmarks on some browsers). Use `event.preventDefault()` and consider `MetaKey` for Mac.
- Empty state for pre-input (dialog just opened) should be different from "no results" — show recent players or a hint like "Тоглогч эсвэл багийн нэр бичнэ үү".
