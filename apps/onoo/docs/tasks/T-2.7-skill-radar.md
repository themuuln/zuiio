## Goal

Skill-shape at a glance — a pentagonal radar chart comparing the player's per-game stats (PTS, REB, AST, STL, BLK) against league average, normalized 0–100.

## Why

A radar chart is the most compact way to show a player's skill profile. It immediately communicates "this player is above average in scoring but below average in rebounding" — a shape the brain reads faster than a row of numbers.

## Implementation Steps

1. **Data helper**: `getLeagueAverages(competitionId)` in `src/app/lib/data.ts` — queries `v_public_leaders` for qualified players (gp ≥ 5 until T-3.4 provides a `qualified` flag), computes mean of pts/reb/ast/stl/blk across all qualified players. Also returns `leagueMaxes` for normalization.
2. **Normalization**: each axis = `(player_value / league_max) × 100`. League max is the max value across all qualified players for that stat. Documented in a code comment (the chart shows normalized values on axes but tooltips show actual per-game values).
3. **`SkillRadar` client component**: Recharts `RadarChart` with 5 axes (PTS, REB, AST, STL, BLK) labeled via `getStatLabel`. Two `Radar` series: player (filled, team color) and league average (muted gray, dashed stroke or translucent fill). Toggle league average visibility with a button.
4. **Lazy load**: import through `chart-sections.tsx` `dynamic()` wrapper.
5. **Integrate into player page**: render after shooting profile under "Чадварын профайл" section heading.
6. **Career mode handling**: in "Карьер" mode (no single competition), radar hides — league-average baseline is per-competition and doesn't aggregate meaningfully. Show a note explaining this.

## Design Decisions

- **Normalization to 0–100**: each axis is independently normalized so shapes are readable. A player who leads the league in PTS (100) but is average in REB (~50) shows a shape that immediately communicates their skill profile. Without normalization, PTS would dominate and REB would appear as a flat line.
- **Actual values in tooltips**: the radial grid shows normalized values (0–100), but tooltips display the actual per-game averages so readers can interpret real numbers.
- **League average gray**: muted `hsl(var(--muted-foreground))` with translucent fill — visible but doesn't distract from the player shape.
- **Toggle button**: "Лигийн дундаж" toggle allows readers to compare with or without the league overlay.
- **5 axes only**: PTS, REB, AST, STL, BLK — the universally tracked basketball stats. Excludes percentages/ratings that don't normalize meaningfully.
- **Qualification gate**: uses gp ≥ 5 until `v_public_leaders` gets a formal `qualified` column (T-3.4). Marked with `TODO(3.4)` comment.

## Risks & Gotchas

- **Empty league averages**: if no qualified players exist (e.g., first game of the season), `getLeagueAverages` could return all zeros. The radar handles this by showing a message or skipping the league series.
- **Qualification threshold**: using gp ≥ 5 is an approximation. When T-3.4 lands, the radar should switch to using the `qualified` flag. Until then, players with <5 games show a note.
- **Radar at mobile**: the 5-axis radar needs adequate viewBox size at 360px. Set `outerRadius` as percentage of container, not fixed px.
- **Color contrast on polar grid**: the polar grid lines must be visible against both light and dark backgrounds. Use `--color-border` for grid lines.
