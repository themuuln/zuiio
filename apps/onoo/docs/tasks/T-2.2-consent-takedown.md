## Goal

The league can hide any player from all public surfaces instantly, and consent capture is recorded.

## Why

Mongolian basketball leagues need a privacy takedown mechanism — when a player requests removal or consent hasn't been given, their identity (name, photo, bio) must disappear from every public page while keeping their statistical contributions intact (box scores stay accurate). This also provides an audit trail for consent recording.

## Design Decisions

- **Masking at the view layer**: all `v_public_*` views use `CASE WHEN p.visibility = 'hidden' THEN 'Нэргүй тоглогч' ELSE p.canonical_name END` — this ensures every data access path is covered without changing application code. Any new public view must follow the same pattern.
- **Stats preserved**: `player_id` is kept in all views; only identity columns are masked. This ensures aggregate stats (team totals, box scores) remain unchanged.
- **No separate takedown table**: visibility lives directly on `players` — simple toggle, no join needed.
- **`v_public_awards` excludes hidden**: awards for hidden players are filtered out entirely — a hidden player cannot appear in "Awards & MVP races" surfaces.

## Risks & Gotchas

- **New views must be patched**: any future public view that exposes player identity MUST include visibility masking. Add this to PR checklist / conventions doc.
- **Admin CRUD route**: the players API POST handler (`src/app/admin/api/players/route.ts`) already passes `visibility`, `consent_recorded_at`, `consent_note` in the create/update body — verify all three are accepted.
- **Consent date format**: the form uses `<Input type="date">` which returns `YYYY-MM-DD` string — the DB column is `timestamptz`, so the route or DB function should cast appropriately.
- **Cache**: if Next.js caches the player page (e.g., `revalidate` or ISR), a hidden player may still show cached identity. The player page uses `dynamic = 'force-dynamic'` or equivalent — verify the page is not statically cached.
