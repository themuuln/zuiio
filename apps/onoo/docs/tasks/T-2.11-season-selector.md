## Goal

Profiles work across seasons — a dropdown selector switches between competitions, and a "Карьер" option aggregates all seasons. Every data section re-scopes to the selected competition.

## Why

Players often compete in multiple leagues and seasons (summer league, winter league, national team). Without a season selector, the page shows only the latest competition's data — hiding the full career story. The career aggregate ("Карьер") is the simplest way to see lifetime totals.

## Data Dependencies

| Entity | Access | Purpose |
|--------|--------|---------|
| `getPlayerCompetitions(playerId)` | Read | Distinct competitions the player has played in (from v_public_box_score → v_public_games) |
| `getPlayerCareerTotals(playerId)` | Read | SUM of pts/reb/ast/gp across all competitions |
| `getPlayerGameLog(playerId, competitionId)` | Read | Returns per-competition games (null competitionId = all games) |
| `getPlayerSeasonAverages(playerId, competitionId)` | Read | Per-competition averages |

## Implementation Steps

1. **Data helpers**: `getPlayerCompetitions(playerId)` returns distinct competitions from `v_public_box_score` → `v_public_games`. `getPlayerCareerTotals(playerId)` returns SUM(pts/reb/ast/gp) across all competitions.
2. **`SeasonSelector` client component**: shadcn `Select` dropdown populated with competition names ("2025 — Зуны лиг") + "Карьер" option. Pushes `?season=<competition_id>` or `?season=career` via `useRouter.push`. Defaults to the latest competition.
3. **Player page wiring**: reads `searchParams.season`. Maps to `competitionId` (null for "career"). Passes `competitionId` + optional `careerTotals` to all sections.
4. **Section scoping**: each data section (hero averages, arc, shooting, radar, milestones, recent games, full game log) is scoped to the selected competition via the competitionId parameter.
5. **Career mode for radar**: radar chart hides in career mode — league-average baseline is per-competition and doesn't meaningfully aggregate. Show explanatory text "Улирал сонгоход чадварын харьцуулга харагдана" (select a season to see skill comparison).
6. **Career totals row**: always visible under the hero card — shows GP, PTS, REB, AST summed across all seasons.

## Design Decisions

- **URL-driven state** (`?season=`): season selection is a `searchParams` push, not a React state. This makes the selector shareable (URL can be bookmarked with a specific season) and works with Next.js server components (server re-renders with new competitionId).
- **Null competitionId = career**: when `season=career`, `competitionId` is `null`. Data helpers treat `null` as "all competitions" and return aggregate values.
- **Latest competition as default**: the selector finds the maximum date across competitions and defaults to that. This ensures the freshest data is shown first.
- **Shadcn Select, not tabs**: seasons can have long names ("2025 — Монгол Улсын Аварга Шалгаруулах Тэмцээн") — a Select dropdown handles this better than tabs.
- **Career radar hidden**: league average is per-competition and doesn't aggregate to a single meaningful value across leagues with different competition strengths. The radar component shows a message instead.

## Risks & Gotchas

- **Keyed component re-rendering**: when switching seasons, child components must re-fetch and re-render with new data. Next.js handles this because the server component re-renders with the new `competitionId`. Client components receive new props.
- **Animation reset on season switch**: `StatNumber` count-up and motion-wrapper animations re-trigger on season switch — this is acceptable and even desirable (feels responsive).
- **Competition ordering**: `getPlayerCompetitions` should return competitions ordered by start date descending so the default (first in array) is the latest.
- **Career totals without average**: career mode shows raw totals (GP, PTS, REB, AST) not per-game averages, since per-game averages across different leagues are misleading.
- **Empty competition list**: a player with zero games shows no competitions. The selector shouldn't render at all in this case — the player page shows empty-state content.
