## Goal

Every showcase surface can rely on player photos, team logos/colors, or a designed placeholder. Admins can upload photos and logos from the player and team management forms.

## Why

The entire player page uses `PlayerAvatar` and `TeamLogo` components that already handle placeholders (initials on team-color background), but the admin upload pipeline and storage infrastructure to supply real photos/logos are not wired. Without this task, every player and team displays as initials — the showcase has no visual identity.

## Design Decisions

- **Storage bucket strategy**: public-read buckets + authenticated WRITE — admin auth is enforced at the API route layer (auth check in photo/logo routes), not in storage RLS, to keep the storage policy simple and debuggable.
- **Upsert on upload**: re-uploading overwrites the same `<id>.<ext>` path, avoiding orphaned objects.
- **Placeholder fallback**: initials from `canonical_name` (player) / `short_code` (team) on `primary_color` or `var(--color-sidebar)` — consistent with the app's existing color system. No generated initials art.

## Risks & Gotchas

- **Storage bucket policy**: if the `20260715160000_storage_buckets.sql` migration hasn't been applied to the hosted Supabase project, uploads will silently fail. Verify with `supabase storage list` or check the Supabase Dashboard.
- **Photo uploader teams integration**: the teams admin page uses `useEntityCrud` which returns `TeamRow` — verify `TeamRow` includes `logo_url` field; if not, extend the type.
- **CORS**: admin API routes are same-origin, so CORS isn't an issue. If ever called from a different origin, add CORS headers.
