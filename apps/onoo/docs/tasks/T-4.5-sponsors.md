## Goal

Sellable "presented by" inventory, league-managed.

## Why

Sponsorships are the league's primary revenue pathway. A managed sponsor placement system — logo slots with date windows — lets the league sell "presented by" placements on high-visibility surfaces (standings, leaders, game pages) and prove placement delivery.

## Implementation Steps

### Database Layer

1. **Migration:**
   - `sponsors` table: `id uuid pk, name text, logo_url text, link_url text, active bool default true, created_at timestamptz default now()`
   - `sponsor_placements` table: `id uuid pk, sponsor_id uuid not null references sponsors on delete cascade, competition_id uuid not null references competitions, slot text not null check (slot in ('standings','leaders','game','recap','award_card','home')), starts_on date not null, ends_on date not null`
   - Storage bucket `sponsor-logos`: public read, admin write
   - View `v_public_sponsor_slots`: active, date-window-valid placements with logo_url and link_url. Hidden players masked per T-2.2 (though sponsors don't reference players directly, apply the pattern for consistency)
   - RLS: tables closed to public
   - `cmd_upsert_sponsor(name, logo_url, link_url, id?)` SECURITY DEFINER
   - `cmd_set_placement(sponsor_id, competition_id, slot, starts_on, ends_on)` SECURITY DEFINER
   - Admin guard follows the same pattern as T-3.5's `cmd_grant_award` guard

2. **Seed data:** Add at least one test sponsor with a placement covering the current date.

### Admin Layer

3. **Admin sponsors page** `src/app/admin/sponsors/page.tsx`:
   - Sponsor list table: name, active status, logo preview
   - Add/edit sponsor form
   - Placement calendar: simple table with slot × date range per competition
   - Logo upload (uses the storage bucket)
   - Admin auth guard via `supabase.auth.getUser()` → 401

4. **Admin API routes:**
   - `POST /api/admin/sponsors` — upsert sponsor
   - `PUT /api/admin/sponsors/[id]` — update sponsor
   - `DELETE /api/admin/sponsors/[id]` — soft-delete (set active=false)
   - `POST /api/admin/sponsors/placements` — set placement

### Public Layer

5. **`SponsorSlot` component:** Create `sponsor-slot.tsx`:
   - Props: `slot: string`, `competitionId: string`
   - Server component: queries `v_public_sponsor_slots` for the given slot + competition
   - Renders: "Ивээн тэтгэгч" caption + logo image (linked to `link_url`) + sponsor name
   - **Returns `null` when no active placement** — never renders an empty box or placeholder
   - Logo renders as an `<Image>` with proper sizing

6. **Mount sponsor slots:**
   - Standings page: below the standings table
   - Leaders page: header area
   - Game page: footer area
   - Recap header: header of recap section
   - Homepage: footer area

## Design Decisions

- `SponsorSlot` returns `null` on no placement — never render an empty container. This avoids layout distortion or "sponsor" labels with nothing behind them.
- Date-window validity is computed in the view, not the app — simple `WHERE starts_on <= current_date AND ends_on >= current_date AND active = true`.
- Admin guard follows the same SECURITY DEFINER pattern as awards — no direct table access from admin API routes.
- Sponsor logos stored in Supabase Storage (same pattern as player photos from T-2.1) for admin-managed uploads.

## Risks & Gotchas

- Storage bucket configuration must exactly mirror the T-2.1 bucket pattern (public read, admin write via SECURITY DEFINER commands). Don't invent a new access pattern.
- The `competition_id` filter in `SponsorSlot` means different competitions can have different sponsors — handle the case where the current page's competition has no placement even if another competition does.
- Date window logic uses `current_date` not `now()` — dates only, no time-of-day issues for day-level windows.
- Admin logo upload: must validate file type (PNG/JPEG/SVG), set proper content-type in storage, and store the public URL. Follow T-2.1's photo upload pattern exactly.
