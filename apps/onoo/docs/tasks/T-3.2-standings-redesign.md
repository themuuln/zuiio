## Implementation Steps

1. **Read existing standings schema:** Inspect `v_public_standings` to confirm available columns (`wins, losses, win_pct, games_back, streak, last_10, points_for/against`) and their types.

2. **`StandingsTable` component:** Create `standings-table.tsx` with:
   - **Columns** at ≥sm: rank number, `TeamLogo` + name (with accent left-border in team `primary_color`), W–L, win% (via `formatStat`), GB, streak chip (W3 green / L2 red), last-10 as ten 6px dots (green/red)
   - **360px minimum columns:** rank, team/W–L, win%. Hide streak chip and last-10 dots on mobile.
   - **Zebra striping** on rows for readability
   - **Sticky header** so column labels remain visible when scrolling
   - **Row tap** links to the team's page (user's own team gets visual distinction)
   - **Playoff line:** horizontal rule after position N (read N from `competitions` config if a `playoff_teams` column exists; else default 4 with a `TODO` comment)

3. **Wire into page:** Replace existing flat content in `standings/page.tsx` with the new `StandingsTable` component, passing fetched data.

4. **Team color accent:** For each row, set a thin left border in the team's `primary_color`. Use inline `style` with the color value from the view.

5. **Streak formatting:** Green background for winning streaks ("W3"), red for losing ("L2"), gray dash for no games.

6. **Last-10 dots:** Ten 6px dots colored green (win) or red (loss). Hidden at 360px via Tailwind `hidden sm:flex`.

## Design Decisions

- Zebra rows via `odd:bg-muted/50` on TR — pure CSS, no JS.
- Playoff line is a horizontal `<Separator>` or styled `<hr>` — the `separator` shadcn component is already available.
- Streak chip uses a small `Badge` variant: green for wins, red for losses.
- Last-10 dots use `rounded-full` divs with green `bg-green-500` or red `bg-red-500` — no chart library needed for 10 dots.
- Left border accent uses inline `style={{ borderLeftColor: team.primary_color }}` since it's dynamic per row.

## Risks & Gotchas

- `games_back` in the view is relative to the top team. Verify the value matches expected computation (could differ from US standard floating-point — check if it's rounded to 0.5 increments).
- Win% formatting: `formatStat` from `@onoo/core` already exists — use it. Verify it returns "0.XXX" format (3 digits) not percentage.
- Team `primary_color` must exist in the view. If absent, spec says the accent should use it — confirm with `v_public_standings` schema.
