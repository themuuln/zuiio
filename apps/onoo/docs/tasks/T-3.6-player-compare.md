## Goal

Visual duel instead of a numbers grid.

## Why

Side-by-side stat grids are dense and hard to scan. Mirrored horizontal bars and a radar overlay make comparisons instantly intuitive — which player leads in each category pops visually.

1. **Audit existing:** Read current `src/app/players/compare/page.tsx` — it's a Client Component using TanStack Query + `/api/stats/compare-players`. Understand the existing data shape.

2. **Extract stat radar:** Move the radar chart component from Task 2.7 into `src/components/stat-radar.tsx` as a reusable component. Accept `players[]` with stat values as props. Keep the existing T-2.7 consumer pointing to the new location.

3. **`CompareBars` component:** Create `compare-bars.tsx` for 2-player mode:
   - Mirrored horizontal bars per stat category
   - Left player's bars grow leftward, right grows rightward
   - Larger value's bar gets team color, smaller gets muted/subtle color
   - Stat label centered between the two bars
   - Numeric value at bar endpoints

4. **`CompareRadar` component:** Create `compare-radar.tsx` for 2-player mode:
   - Overlay radar chart with both players' stat lines
   - Different colors per player (team primary colors)
   - Legend showing player names

5. **Page restructure:** Refactor `compare/page.tsx`:
   - **2 players:** Show mirrored bars + radar overlay. `PlayerAvatar` header row with jersey numbers.
   - **3–5 players:** Fall back to the existing grid layout + grouped bars. No radar (too cluttered).
   - Keep TanStack Query data fetching and the existing API endpoint untouched.

6. **Responsive:** Mirrored bars layout must work at 360px — stack vertically if needed.

## Design Decisions

- Mirrored bars use flexbox with `flex-direction: row-reverse` for the left player — pure CSS, no chart library needed for the bar comparison.
- Radar always uses Recharts (already available from T-2.4) — the overlay uses a single `<RadarChart>` with two `<Radar>` children.
- Team color for bar fill: use inline `style` with the team's `primary_color` from the API response. Loser bar uses `bg-muted` or `opacity-50`.
- The extracted `stat-radar.tsx` lives in `src/components/` (shared, not route-local) so any page can use it.

## Risks & Gotchas

- The existing API response must include team `primary_color` and `jersey_number`. If not, the UI falls back gracefully (no color = default blue, no jersey = omit).
- For 3+ players, radar overlay becomes unreadable — fall back explicitly and simply don't render the radar.
- The radar extraction from T-2.7 must leave T-2.7 working. Update the import in T-2.7's component to point to `src/components/stat-radar.tsx`.
- Bar comparison for stats with different scales (e.g., PTS vs BLK) — bars are normalized within each stat pair, not across stats. Each bar pair represents the two players' values for that category.
