## Goal

Compute and display lineup efficiency analysis using existing substitution events in `stat_events`. Show top 5 lineups by NETRTG, worst lineups, per-lineup scoring, and lineup +/-.

## Why

This is THE killer analytics feature. No amateur basketball platform in Mongolia offers lineup +/- analysis. Team owners and coaches would pay for NBA-level lineup insights. The data already exists in `stat_events` (substitution events) — it's completely unused.

## Data Dependencies

| Entity | Access | Purpose |
|--------|--------|---------|
| `stat_events` | Read only | Substitution events (player in/out, team_id, game_id, period, clock) |
| `game_team_stats` | Read only | Team scoring context per game |

## Implementation Steps

1. Analyze `stat_events` substitution data pattern:
   - Read a sample of substitution events to confirm payload structure
   - Map: `player_in`, `player_out`, `period`, `clock_seconds`, `team_season_id`
2. Create `packages/core/src/stats/lineup-analysis.ts`:
   - `computeLineups(events, teamId)` → array of lineup periods
   - A "lineup" = set of 5 players on court at any time
   - For each lineup: calculate minutes played, points scored, points allowed, NETRTG, PTS/poss, OREB%, etc.
   - Sort by minutes played (minimum threshold: 5 min) then NETRTG
3. Create `getLineupsByTeam()` in data.ts:
   - Fetch stat_events for completed games filtered by team
   - Pass to core computation
   - Return top 10 and bottom 5 lineups
4. Create LineupAnalysis component:
   - Table: lineup (player names), minutes, +/- , ORtg, DRtg, NETRTG, PTS
   - Highlight top 3 green, bottom 3 red
   - Show "lineup card" with 5 player avatars in formation layout
   - Collapsible per-game breakdown
5. Add to team analytics page: `<LineupAnalysis />` section

## Risks & Gotchas

- **Data quality**: Substitution events must be consistently recorded. If scorekeepers don't log subs, lineups will be sparse. Need to handle gracefully with "Хангалттай өгөгдөл байхгүй" state.
- **Computation complexity**: 5-player lineup combinations grow exponentially. For amateur teams with 10-12 players, it's manageable (~200 lineups max per team per season).
- **Performance**: Querying `stat_events` for all games and computing lineups on-the-fly may be slow. Consider caching or a materialized view if needed.
- Start with computation from raw events (proven correct), optimize later if slow.
