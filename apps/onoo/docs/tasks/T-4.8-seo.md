## Goal

Profiles findable via Google/Facebook search, not just shared links.

## Why

Without sitemaps and proper metadata, search engines can't index the league's content. Sitemaps, robots.txt, and unique metadata per page ensure that player profiles, game pages, and standings appear in Google results when users search for Mongolian basketball.

## Implementation Steps

1. **Find canonical site URL env var:** Grep the repo for `.env` handling patterns — find the variable name used for the site URL (`NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_BASE_URL`, or similar). Use that with a safe fallback (e.g., `http://localhost:3000` for dev).

2. **`sitemap.ts`:** Create `src/app/sitemap.ts`:
   - Static routes: `/`, `/games`, `/leaders`, `/standings`, `/players`
   - Dynamic entries:
     - Players: all entries from `v_public_players` (T-3.8 view — hidden players must be excluded)
     - Games: last 500 from `v_public_games` with `lastModified` where available
     - Teams: all active teams
   - Set `lastModified` date for each entry (use game date, player updated_at, or static)
   - Base URL from the env variable with fallback

3. **`robots.ts`:** Create `src/app/robots.ts`:
   - Allow all crawlers
   - Disallow: `/admin`, `/tracker`, `/api`, `/embed`
   - Point to the sitemap URL

4. **Metadata audit pass:** For every public page, ensure `generateMetadata` provides:
   - Unique `title` (pattern: "Player Name — Team — Оноо" or "Team vs Team — Оноо")
   - `description` with a real stat (e.g., "32.5 PPG, 12.3 RPG this season")
   - `alternates.canonical` with the correct URL
   - Do NOT override `openGraph.images` if file-convention OG images exist (T-4.1)
   - Hidden players (T-2.2) must be excluded from all sitemap and metadata

## Design Decisions

- Title pattern: descriptive and unique per page type — "PlayerName — TeamName — Оноо" for players, "TeamA vs TeamB — Оноо" for games, "League standings — Оноо" for standings.
- Descriptions include a real stat where possible — improves CTR from search results. For the homepage, description can be a league tagline.
- Sitemap includes last 500 games only — full history is unnecessary for SEO and would make the sitemap too large.
- Hidden player exclusion is critical — if a player has exercised their takedown right (T-2.2), their profile must not appear in sitemap or search results.

## Risks & Gotchas

- The env variable name for site URL is unknown — grep for `NEXT_PUBLIC_*` in `.env*` files, `next.config.ts`, and existing `generateMetadata` calls that set canonical URLs. Use the found variable with a safe fallback.
- Hidden player exclusion: if T-2.2 uses a `hidden` flag or `consent_status` column on `players`, the sitemap must filter on it. If the column doesn't exist yet, add a filter placeholder and handle gracefully.
- Dynamic sitemap entries for teams: if teams don't have a public listing endpoint, use the existing `getTeamBySlug` pattern or add a `getAllTeams` helper.
- Sitemap size: with ~500 games + all players + all teams, the sitemap should be well under the 50MB/50k URL limit. Pagination is not needed.
- Metadata description should be generated server-side with real data — e.g., for a player: "Төмөржүү Идэр — 32.5 PPG, 12.3 RPG, 6.8 APG — Увс Хангарьд" — not static text.
