## Goal

Player stat lines tick up during the game.

## Why

A live box score where numbers change in realtime creates the most engaging possible experience for fans watching from home. Seeing a player's point total tick up after each made shot is the closest thing to being at the game.

## Design Decisions

- Changed cell flash uses a CSS-only approach: set `data-changed` attribute on the cell, apply a CSS `@keyframes` animation for background color flash that transitions to transparent over ~1.5s. No JS animation library.
- Cell comparison: the hook stores a previous snapshot map of `{ playerId: { pts, reb, ... } }`. On each refresh, diff against the new values and set `data-changed` on changed cells.
- CSS `order` property for re-sorting: after data refresh, the container uses `display: flex` with `flex-direction: column` and each row gets an `order` based on rank. This avoids DOM reordering which causes layout thrash.
- Status transition: `use-live-game` returns the game status. When the component detects `final_pending_review`, it conditionally renders the recap header from T-4.3 instead of the live header. This is a pure component swap, no routing.

## Risks & Gotchas

- The changed cell flash relies on comparing entire previous snapshot. The hook must store the box score snapshot from the previous refetch and compute diffs. On the first render, no cells should flash (no previous state to compare against).
- CSS `order` re-sorting: flex items with `order` set dynamically may not transition smoothly. Test that it doesn't cause visible jank — if it does, accept the brief reorder (spec says "CSS order — no layout thrash on every event," meaning no forced reflows, not necessarily smooth animation).
- Provisional badge: when game transitions to verified (admins approve), the badge should update without reload — the refetch signal triggers a render with the new status and `is_provisional` becomes false.
- `use-live-game` hook must either return box score data or expose a `refetch` function that the box score component can call after the hook's own refetch. If they're separate, synchronize them.
