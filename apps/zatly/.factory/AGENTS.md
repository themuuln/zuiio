# Zatly — Project Instructions for Droid

## Task Tracking

After completing any user-requested task, you MUST update the project tracker at `planning/TRACKER.md`:
- Mark finished tasks as `✅ DONE`
- Update the Session Log with date, sprint, and summary of work done
- If a task was partially completed or a new task was discovered, add it to the appropriate sprint or backlog

## When Planning or Prioritizing Work

Always consult the strategic context in both files before starting:
- `masterPlan.md` — contains competitor weaknesses, user pain points, market gaps, and the "why" behind each priority
- `planning/TRACKER.md` — each sprint section includes a `Strategic context` block explaining which competitor weaknesses or market opportunities that sprint targets

If asked "why should we build X" or "what's the priority," reference:
- The **user pain points table** in Section 14.6 of masterPlan.md
- The **feature gap analysis** in Section 14.5
- The **competitor analysis** in Section 14.3
- The **immediate priorities** table in Section 0.2

## Reference

- `planning/TRACKER.md` — sprint planning, task status, session log, KPI tracking
