# Map & Lost Horse Finder — Implementation Plan

## Overview

Add an offline-capable map feature with lost horse reporting, geofence-based search areas, and nearby horse discovery. Horse owners in rural Mongolia (often without internet) can report lost horses, define search areas with geofence circles, and discover other horses/owners in their vicinity. Uses `maplibre_gl` with vector tiles (PMTiles/MBTiles) for offline-first architecture.

## Desired End State

1. Horse owner opens Map tab → sees offline map of Mongolia (bundled vector tiles)
2. Owner reports lost horse → horse appears on map with red marker + search radius circle
3. Other owners in area see notification: "Хаяж морь ойрхон байна" (Lost horse nearby)
4. Owners can see other horses in their area (with permission) — discoverability
5. Geofence alerts: when horse crosses defined boundary, owner gets notified
6. All map interactions work offline — sync when connectivity returns

## What We're NOT Doing

- Real-time GPS tracking (requires hardware)
- Turn-by-turn navigation to lost horse
- Satellite imagery (too large for offline)
- Horse-to-horse communication
- Paid map tiles (using free Protomaps/OpenFreeMap)

## Architecture

### Offline-First Map Stack

```
┌─────────────────────────────────────────┐
│  Presentation: MaplibreMap widget       │
│  ├── MapScreen (main map view)          │
│  ├── LostHorseMarker (red pulsing)      │
│  ├── SearchAreaCircle (geofence)        │
│  └── HorseClusterMarker (nearby horses) │
├─────────────────────────────────────────┤
│  Application: Map providers             │
│  ├── mapStateProvider                   │
│  ├── lostHorsesProvider                 │
│  ├── nearbyHorsesProvider               │
│  └── geofenceAlertsProvider             │
├─────────────────────────────────────────┤
│  Data: Map + Location repositories      │
│  ├── OfflineTileManager (MBTiles)       │
│  ├── GeofenceService (distance calc)    │
│  ├── LocationService (GPS)              │
│  └── SyncQueue (pending reports)        │
├─────────────────────────────────────────┤
│  Domain: Map models                     │
│  ├── LostHorseReport                    │
│  ├── SearchArea (geofence circle)       │
│  ├── HorseLocation                      │
│  └── GeofenceAlert                      │
└─────────────────────────────────────────┘
```

### Tile Storage Strategy

| Source | Format | Size | Use |
|---|---|---|---|
| Protomaps Mongolia extract | PMTiles (vector) | ~200-500MB | Base map, bundled in assets |
| Downloaded regions | MBTiles (vector) | Variable | User-initiated zoom 13-16 |
| Cached tiles | FMTC / local cache | Variable | Previously viewed areas |

## Performance Considerations

- Vector tiles (PMTiles) load faster than raster — no tile stitching
- Geofence checks are pure math — no network latency
- Marker clustering handles 100+ horses without lag
- Offline tile copy is one-time (~200-500MB for Mongolia)
- Location updates batch every 30 seconds to save battery
